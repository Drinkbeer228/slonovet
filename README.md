# СлоноВет 2.0

Суточное дежурство киперов и заявки ветврача для животных.

- **Кипер** принимает смену (обязательная проверка: электропастух, замки, вещи у ограждения, вода), видит заявки врача, отмечает состояние слоних в одной таблице, кормление, сено, сбор мочи, ветки и уход, уборку, обогащение среды, делает записи с фото и сдаёт смену с заметкой.
- **Склад**: каши и зерно списываются сами, когда кипер отмечает кормление; сено — по числу выданных тюков; овощи — по весу, который кипер вписал в 19:00. Мешки показаны «батарейкой». Любой кипер вносит приход и поправляет остаток.
- **Ветврач** видит динамику за 14 смен, что пишут киперы, создаёт заявки (один раз / каждую смену / каждое кормление, с фото, срочно) и видит, кто и когда их выполнил. Может менять рацион.
- **Директор** видит всё: обзор, журнал, склад и рацион, ставит заявки. Людей, рацион, склад и смены не меняет.
- **Админ** заводит людей по логину и паролю — без настоящей почты.

Приложение работает без интернета: всё пишется на телефон и отправляется в Supabase, когда появится сеть.

## Посмотреть без сервера

`npm install` → `npm run dev` → на экране входа нажать «Кипер», «Врач» или «Админ». Это демо с примерными данными, только на этом устройстве.

## Подключение Supabase (один раз)

1. **База.** Supabase → SQL Editor → вставить весь `supabase/migrations/001_init.sql` → Run.
2. **Вход без почты.** Authentication → Sign In / Providers → Email: выключить **Confirm email**. Регистрацию (Allow new users to sign up) лучше тоже выключить — людей заводит админ.
3. **Функция для админа.** Edge Functions → Deploy a new function → имя `admin-users` → вставить `supabase/functions/admin-users/index.ts` → Deploy.
   Если пользуетесь CLI: `supabase functions deploy admin-users`.
4. **Первый админ.** Authentication → Users → Add user → email `admin@slonovet.local`, придумать пароль, галочка Auto Confirm.
   Затем в SQL Editor:
   ```sql
   update public.profiles set role = 'admin', active = true, full_name = 'Администратор' where login = 'admin';
   ```
5. **Ключи в приложение.** Project Settings → API: скопировать Project URL и anon public key в `.env.local` (образец в `.env.example`) — или вписать их на экране входа («Подключить сервер Supabase»).
6. Войти логином `admin`, открыть меню (кружок справа сверху) → **Люди** → добавить киперов и врача. Логин и пароль передать людям.

## Как устроено

```
src/
  domain/      типы, слонихи и показатели, смена, склад, действия, демо-данные
  lib/         IndexedDB, локальное хранилище + очередь отправки, синхронизация, вход, фото
  screens/
    keeper/    смена: приём, заявки, состояние, кормление, «за смену», сдача
    vet/       обзор (динамика), заявки
    admin/     люди
    DietScreen, StockScreen, JournalScreen
  ui/          кнопки, шторки, иконки
supabase/      SQL-схема с правами по ролям, функция admin-users
```

- Каждое изменение сразу пишется в IndexedDB и, в облачном режиме, в очередь `outbox`. `lib/sync.ts` раз в минуту, при появлении сети и при открытии приложения отправляет очередь и забирает чужие изменения (по `updated_at`).
- Права проверяет сама база (RLS): смены, отметки заявок и склад пишут кипер и админ; заявки и рацион — врач и админ; настройки склада (вес мешка, «кг в гарце») — админ.
- Фото сжимаются на телефоне и лежат в приватном хранилище `photos`.

## Что поправить под себя

- `src/domain/elephants.ts` — показатели таблицы и варианты симптомов, пункты проверки при приёме.
- Вес мешков — в приложении (Склад → позиция, под админом).
- Мерный совок: Склад → «Мерный совок (гарец)», под админом. Достаточно один раз взвесить полный совок овса — остальное зерно пересчитается по плотности (примерно; каждую позицию можно поправить отдельно).
- Овощи идут «по весу»: в 19:00 кипер ставит галочку и вписывает, сколько кг выдал (сумма тазов). Это и списывается со склада, и по этим цифрам считается «хватит на N дней». Если врач впишет в «Рационе» фиксированные кг, списание пойдёт по рецепту.

## Темы

В меню (кружок справа сверху) → «Вид»: тёмная, светлая и «Пиксель». Выбор запоминается на телефоне.
