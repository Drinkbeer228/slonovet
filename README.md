# СлоноВет

Журнал слоновника в телефоне: приём и сдача дежурства, состояние слоних, кормление, фураж, назначения ветврача. Заменяет бумажный журнал и работает без интернета.

**Адрес:** https://slonovet.ru

## Что умеет

- **Дежурство.** Кипер принимает его по проверке из 7 пунктов и коду от сдающего, отмечает только то, что не норма (таблица: Общее, Сон, Еда, Вода, Моча, Кал, Ноги), ставит галочки кормления, считает баки, ветки и мешки, сдаёт с заметкой и подтверждением «осмотрел всех трёх».
- **Назначения и задачи.** Врач, директор или любой сотрудник ставит задачу (можно с фото) (один раз / каждое дежурство / каждое кормление, с вариантами ответа, фото, срочно). Кипер отвечает одной кнопкой внутри дежурства.
- **Журнал.** Как бумажный: выбрал день (стрелки, календарь с цветными днями) — видишь таблицу отметок и подробности дежурства. Сверху само появляется «Требует внимания», если что-то плохо или тянется несколько дежурств подряд.
- **Фураж.** Каши, зерно и овощи (картофель, морковь, свёкла) списываются по кормлению в кг, сено по тюкам, мешки по счётчику. Овощи и фрукты учитываются в кг, как крупы (плюс мешки/ящики); выдача на манеж, репетицию или шоу — «Вне рациона» в дежурстве, остальные расхождения — поправка остатка. Видно, на сколько дней хватит. Позиции можно добавлять (группа, название, штуки / кг / мешки), переименовывать и удалять; то, что списывается само, удалить нельзя.
- **Закупки.** Любой сотрудник просит купить (мешки, сено, ветки, каши или что-то своё) — в «Фураже» или в «Заявках» → «Закупки». Администратор или директор отмечает «Заказано» (можно с датой доставки) и «Привезли» прямо в строке заявки.
- **Рацион, Переезд, Справка** (распорядок, корма, сигналы, безопасность и «Почему так?»), **Мои достижения** — личные значки кипера за качество работы, без рейтинга.
- **Без сети.** Всё пишется в телефон и уходит на сервер при первой связи. Отметки двух телефонов в одном дежурстве не затирают друг друга.

## Роли

Все видят все разделы. Меняет только хозяин раздела, остальные видят «Только просмотр — меняет …».

| Роль | Что меняет |
|---|---|
| Кипер | дежурство, фураж: приход, остатки, позиции |
| Ветврач | рацион, назначения; закрывает любые задачи |
| Директор | назначения, закупки, фураж, люди (кроме системных админов) |
| Администратор | фураж и его настройки, закупки, киперы и врачи |
| Системный админ | всё |

Хозяева разделов описаны в `src/domain/access.ts`, а сами права проверяет база (RLS).

## Как устроено

- **Фронтенд:** React 19, Vite, Tailwind 4, TypeScript. PWA (vite-plugin-pwa), ставится на главный экран.
- **Данные на телефоне:** IndexedDB + очередь отправки (`src/lib/store.ts`). Смены отправляются патчами: только изменённые поля (`src/lib/patch.ts`, функция `apply_shift_patch` в базе).
- **Сервер:** свой VPS у Beget (Россия). На нём nginx с HTTPS (Let's Encrypt, продлевается сам) и свой Supabase в Docker на `api.slonovet.ru`: Postgres с правами по ролям (RLS), вход по логину без почты (`login@slonovet.local`), приватное хранилище фото, функция `admin-users` для заведения людей. Наружу открыты только нужные приложению пути API, панель Supabase — через SSH-туннель.
- **Журнал действий:** что нажимают и где падает приложение — таблица `events`, читают админ и директор.

## Запустить у себя

```bash
npm install
npm run dev
```

На экране входа — «Посмотреть пример без входа»: демо с примерными данными, только на этом устройстве.

Для работы с сервером скопируйте `.env.example` в `.env.local` и впишите адрес и публичный ключ Supabase.

Проверки: `npm run lint`, `npm test`, `npm run build`.

## Выкладка

Push в `main` → GitHub Actions проверяет (lint, тесты), собирает и по SSH кладёт сайт на сервер в `/var/www/slonovet` (пользователь `deploy`, ключ — секрет `DEPLOY_SSH_KEY`). Адрес и публичный ключ API — в `.env.production`.

Ключ выкладки на сервере ограничен: в `~deploy/.ssh/authorized_keys` у него `command="/usr/bin/rrsync -wo /var/www/slonovet"` — только запись в папку сайта, без команд и без доступа к копиям. Путь в `deploy.yml` поэтому относительный, а перед выкладкой она проверяет, что ограничение на месте, и без него останавливается.

## Новая база с нуля

1. Поднять Supabase (официальная сборка для Docker, `setup.sh`), в `.env`: `SITE_URL`, `SUPABASE_PUBLIC_URL`, `API_EXTERNAL_URL`, `DISABLE_SIGNUP=true`, `ENABLE_EMAIL_AUTOCONFIRM=true`. Дождаться, пока запустятся все сервисы: таблицы хранилища фото создаёт сервис storage.
2. Накатить миграции: `./server/migrate.sh apply` (свой адрес — через `SLONOVET_SSH`, см. начало скрипта).
3. Положить функцию `supabase/functions/admin-users` в `volumes/functions/admin-users/`.
4. Завести первого пользователя (`<логин>@slonovet.local`) и дать ему роль `admin` и `active = true` в таблице `profiles`.
5. Остальных людей заводят в приложении: меню → «Персонал».

## Миграции

- `./server/migrate.sh` — какие файлы из `supabase/migrations/` применены на сервере, какие ждут, какие изменены после применения.
- `./server/migrate.sh apply` — свежая копия базы, затем недостающие миграции по порядку. Каждая вместе с записью в учёт — одна транзакция: упала — не применилось ничего.
- Учёт — таблица `slonovet.migrations` на сервере (схема закрыта от приложения).
- Правила: миграции только добавляющие и повторяемые (`if not exists`, `drop … if exists`); применённый файл не правим — новую правку оформляем новым файлом.

## Резервные копии

- **Каждую ночь** (03:30) сервер копирует всю базу (хранит 14 дней) и дописывает новые фото в зеркало — `server/backup.sh`, на сервере `/opt/slonovet/backup.sh`, копии в `/opt/slonovet/backups` (читает только пользователь `slonovet-backup`).
- **Раз в неделю** `backup.yml` забирает свежую копию базы (без фото) своим ключом (секрет `BACKUP_SSH_KEY`, на сервере — `rrsync -ro`, только чтение копий), проверяет, что ей меньше двух суток, шифрует (секрет `BACKUP_PASSPHRASE`) и хранит 90 дней в Actions → «Резервная копия». Расшифровать: `gpg -d slonovet-backup.tar.gz.gpg | tar xz`.
- **Проверка восстановления:** `/opt/slonovet/restore-check.sh` поднимает временный Postgres того же образа без сети, заливает копию и сверяет с рабочей базой число строк, права и функции. 26.10.2026: все таблицы совпали; ошибки только по двум служебным ролям Supabase (realtime, webhooks), которых нет в голом образе.
- **Восстановить на сервере:** поднять Supabase как в «Новая база с нуля» (шаг 1), затем в контейнере `supabase-db`: `pg_restore --clean --if-exists -U supabase_admin -d postgres db-latest.dump` (`postgres` в этом образе не суперпользователь) и вернуть фото: `rsync -a /opt/slonovet/backups/photos/ /opt/supabase/volumes/storage/`.
