Ты — продуктовый дизайнер мобильных интерфейсов. Сделай дизайн-ревью приложения «СлоноВет» глазами пользователя телефона и поправь то, что мешает. Старую переписку читать не нужно — всё нужное ниже.

## Что это за приложение

Электронный журнал суточного дежурства киперов цирковых слонов (три слонихи: Претти, Марго, Одри). Им пользуются киперы на ходу, одной рукой, часто в перчатках, в слоновнике, где грязно и шумно. Ещё — ветврач и админ.

Код: `~/Загрузки/slonovet` (React 19 + Vite + Tailwind 4, TypeScript). Данные — Supabase, но для ревью он не нужен: есть демо-режим.

Главные экраны:
- **Смена** (`src/screens/keeper/ShiftScreen.tsx` и соседние файлы): приём смены (чек-лист ✓/✗, замечания, код передачи), «Назначения и задачи», таблица состояния (по умолчанию всё «норма», тап → внимание → плохо), кормление (07:00 зерносмесь, 13:00 и 17:00 каша, 19:00 овощи — наполнение тазов), «Туалет» (моча в бак / мимо, кал — счётчики), ветки, мешки, мытьё, записи, сдача смены.
- **Рацион**, **Склад** (мешки «батарейкой», «хватит на N дней»), **Журнал** (календарь как активность GitHub + таблица смены как бумажный журнал).
- Из меню (кружок справа сверху): **Справка**, **Мои достижения**, **Переезд** (чек-лист сборов с «кто собрал»), у админа — **Персонал**.
- У врача: **Обзор**, **Заявки** (назначения с вариантами ответа кнопками).

UI-кит: `src/ui/kit.tsx`, иконки `src/ui/Icon.tsx`, цвета и шрифт — `src/index.css`.

## Как смотреть

```bash
cd ~/Загрузки/slonovet && npm install && npm run dev
```

Открыть `http://localhost:3000` в окне **375×812** (телефон). На экране входа внизу кнопки «Кипер», «Врач», «Админ» — демо с примерными данными. Чтобы сбросить демо: очистить IndexedDB и localStorage сайта.

Пройди как кипер: приём смены (код в демо подсказан на экране) → вся смена сверху вниз → сдача. Потом врач и админ.

## Что важно владельцу (руководит киперами)

- **Только телефон.** Компьютерная версия не интересует. Всё проверяй на ширине 375 px.
- **Проще бумажного журнала**, иначе не будут пользоваться. Минимум обязательного ввода, всё что можно — одним тапом, необязательное — необязательно.
- Не любит: лишние поля, «заводскую» рутину, цветовые «блочные» системы (уже пробовали — откатили), переходы в другой раздел ради справки. Любит: шторки снизу (как «почему?»), понятные короткие подписи, похожесть на их бумажный журнал (Общее, Сон, Еда, Вода, Моча, Кал; «+» норма).
- Язык — русский, разговорный, без канцелярита.

## Что проверить

1. Иерархия и сканируемость экрана «Смена»: он длинный — легко ли найти нужный блок посреди дня? Что выше, что ниже по частоте использования?
2. Размеры попаданий (кнопки ≥ 44 px), расстояния между соседними кнопками, риск промахнуться в перчатке.
3. Контраст и читаемость на улице/в полутьме (тёмная тема), размер шрифтов, переносы длинных подписей, обрезанный текст.
4. Единообразие: одинаковые вещи выглядят одинаково (кнопки, чипы, счётчики, шторки, пустые состояния, подтверждения).
5. Тексты: понятно ли без объяснений, нет ли длинных/канцелярских подписей, одинаковые ли слова для одного и того же.
6. Сдвиги вёрстки при тапе (раскрытие блоков под пальцем), перекрытие нижней панелью и клавиатурой, отступы снизу.
7. Пустые и крайние состояния: нет смены, нет назначений, нет сети, длинные имена, много записей.

## Как работать

- Сначала пройди всё и составь список находок по приоритету (что реально мешает кипер у слона → что просто некрасиво). К каждой — экран, что не так, как исправить. Скриншоты по возможности.
- Мелкие правки внешнего вида (отступы, размеры, тексты, выравнивание, контраст) — делай сразу и проверяй на 375 px.
- Всё, что меняет поведение, убирает/добавляет поля, меняет данные или структуру экранов — **сначала предложи и спроси**.
- Не трогай Supabase, схему базы (`supabase/`), синхронизацию (`src/lib/sync.ts`, `store.ts`, `idb.ts`), вход и права.
- После правок: `npm run lint` (проверка типов) и `npm run build` без ошибок.
- В конце коротко: что исправил, что предлагаешь и ждёт решения.
